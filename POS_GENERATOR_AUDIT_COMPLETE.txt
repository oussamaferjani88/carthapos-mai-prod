3.  WORKFLOW / STEP FLOW COMPARISON
══════════════════════════════════════════════════════════════════════════════

ADMIN (POSGeneratorPage.jsx - 625 lines, 1-indexed steps):
  Step 1      → Basic Config (client + sector)      → canProceed
  Step 2      → Module Selection                     → canProceed
  Step 2.5    → Template vs Custom Choice (inline)   → choose
  Step 2.7    → Template Selection (4 templates)     → apply + goto
  Step 3      → Custom POSCustomizer (inline)        → device preview

  Step 4      → License + USB Config                 → canProceed
  Step 5      → Results + Download                   → reset

  Step 1      → Module Selection                     → canProceed

  Step 3      → POSCustomizer (full, fills page)     → onSave→next
  Step 4      → License Config → Generate            → canProceed
  Step 4 (alt)→ Results (when generationResult set)  → new POS

STEP FLOW DIFFERENCES:
  - Frontend combines what Admin does in steps 2.5+2.7+3 into
    step 2 (template choice) + step 3 (customizer)
  - Frontend uses 0-indexed steps, admin uses 1-indexed with decimal sub-steps
  - Frontend's step 3 is always "full" mode customizer; admin has both
    "full" (separate showCustomizer) and "inline" (step 3 with sidebar)
  - Frontend doesn't implement Admin's step 2.7 template selection UI
    (4 pre-built template cards with features/badges)
  - Frontend doesn't have "directConvert" or "quickTest" buttons
