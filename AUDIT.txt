**Tech Stack:**
- **Admin**: React + Vite + Tailwind + shadcn/ui
- **Backend**: Node.js + Express + Prisma ORM + PostgreSQL
- **POS Template**: Electron + React + SQLite (better-sqlite3) + Tailwind + shadcn/ui
- **IPC Layer**: Electron IPC (`ipcMain.handle`/`ipcRenderer.invoke`) with 100+ registered channels

**Events Dispatched:** `sale-completed` (→ Dashboard, Products, Reports), `kitchen-order-created` (→ Kitchen)

### Backend (`ipc-sales-handlers.cjs`)

**Handlers:**
| Channel | Operation |
|---------|-----------|
| `add-sale` | Creates sale + sale_items, deducts stock (if non-pending), creates kitchen orders, updates customer loyalty, frees table |
| `add-held-order` | Stores suspended order in `held_orders` |
| `delete-held-order` | Deletes a held order |
| `restore-held-order` | Returns held order data |
| `get-active-shift` | Queries `shifts WHERE status='open'` |
| `open-shift` | Inserts new shift record |
| `close-shift` | Updates shift with closing amounts, calculates difference |

**Database Tables:** `sales`, `sale_items`, `products`, `stock_movements`, `customers`, `kitchen_orders`, `shifts`, `restaurant_tables`, `held_orders`

### Critical Relationship Map:
```
Sales → Products (stock deduction on sale)
Sales → Kitchen (order creation on sale)
Sales → Tables (status update on sale)
Sales → Customers (loyalty points)
Sales → Shifts (shift totals)
Sales → Reports (all sales data feeds reports)
Sales → Dashboard (real-time stats)
```

### Key Issues:
| Severity | Issue |
|----------|-------|
| Critical | `restore-held-order` returns order but never deletes it — ghost data |
| Critical | `complete-pending-sale` never deducts stock or creates kitchen orders |
| High | `add-sale` kitchen order creation is fire-and-forget — silent failure |
| High | `add-sale` frees table even for pending sales |
| Medium | `add-sale` doesn't validate total/subtotal/tax consistency server-side |
| Medium | Loyalty points awarded inconsistently between pending and non-pending |

## Summary of Issues Found

### By Severity

| Severity | Count | Key Examples |
|----------|-------|-------------|
| **Critical** | 4 | Raw SQL from renderer, restore-held-order ghost data, complete-pending-sale skips stock/kitchen, SQL injection in query/execute |
| **High** | 8 | Fire-and-forget kitchen orders, no referential integrity on deletes, race conditions on stock deduction |
| **Medium** | 14 | No server-side total validation, inconsistent timezone handling, missing duplicate checks |
| **Low** | 10 | Inconsistent error handling, silent failures, naming inconsistencies |

### Top 5 Priorities

1. **Security: Restrict `database:query`/`database:execute`** — Raw SQL from renderer is a full RCE vector. Add whitelist of allowed queries or use named prepared statements.

2. **Data Integrity: `complete-pending-sale` must deduct stock + create kitchen orders** — Currently pending sales bypass inventory and kitchen entirely, even when completed.

3. **Data Integrity: `restore-held-order` must delete the held order** — Currently returns data without deleting, allowing infinite duplicate restores.

4. **Referential Integrity: Add checks to `delete-product`, `delete-table`, `delete-kitchen-department`, `delete-vat-rate`** — All currently orphan dependent records.

5. **Atomicity: Stock deduction in `add-sale` should use atomic SQL** — `UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?` prevents overselling.

---

## Fixes Applied

### Fix 1: Security — Raw SQL lockdown (`ipc-database-handlers.cjs`)
- `database:query` — now enforces SELECT-only + blocks forbidden SQL keywords (INSERT/UPDATE/DELETE/DROP/ALTER/CREATE/REPLACE/TRUNCATE)
- `database:execute` — completely blocked from renderer (throws "Accès refusé")
- `database:transaction` — completely blocked from renderer
- Added new `update-product-family` named handler for Products.jsx

### Fix 2: `complete-pending-sale` now deducts stock + creates kitchen orders (`ipc-sales-handlers.cjs`)
- Fetches sale items from DB
- Atomic stock deduction per item (`WHERE stock >= ?`)
- Records stock movements with "complétée" reason
- Creates kitchen orders by department (same logic as `add-sale`)
- Updates shift totals + customer stats

### Fix 3: `restore-held-order` deletes after restore (`ipc-sales-handlers.cjs`)
- `DELETE FROM held_orders WHERE id = ?` after returning the data
- Prevents ghost orders and infinite restore loops

### Fix 4: Referential integrity checks on all delete handlers
- **`delete-product`** — checks `sale_items`, `stock_movements`, `kitchen_orders` (blocks if any exist)
- **`delete-table`** — checks `sales`, `held_orders`, `table_reservations` (blocks if any exist)
- **`delete-kitchen-department`** — checks `products.preparation_department`, `kitchen_orders.department` (blocks if any exist)
- **`delete-vat-rate`** — checks `products.vat_rate_id` (blocks if any exist)

### Fix 5: Atomic stock deduction in `add-sale` (`ipc-sales-handlers.cjs`)
- Changed from read-then-write to `UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?`
- Returns error with product name + available/requested quantities if insufficient stock
- Same atomic pattern applied to `complete-pending-sale`
