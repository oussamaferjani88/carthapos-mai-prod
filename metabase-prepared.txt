2. How embedding works (CE public sharing)
────────────────────────────────────────────

  1. BI specialist builds dashboard in Metabase UI
  2. Enables sharing → "Make this dashboard public" → gets a public UUID
  3. Specialist registers template via POST /api/bi/dashboard-templates
     with { businessType, metabaseDashboardId, name, embedType: "public",
     embedPublicUuid: "<uuid>" }
  4. Admin links a client BiDashboard to metabaseDashboardId
  5. Client opens BIDashboardViewer → calls GET /:id/embed
  6. Frontend renders iframe if all 3 conditions met:
     a) METABASE_EMBED_ENABLED=true
     b) template.embedType === "public"
     c) template.embedPublicUuid is non-null
     Otherwise shows appropriate fallback (open button, pending message)

4. Architecture notes
────────────────────────────────────────────

  • No JWT embedding — Metabase CE only supports public sharing
  • No RLS — multi-tenant isolation must be done via per-tenant
    PostgreSQL schemas or separate databases in production
  • Embedding gated by METABASE_EMBED_ENABLED — safe to leave false
    until dashboards are ready
  • All embed info comes from a single backend endpoint so the frontend
    is a pure consumer with no hardcoded embed logic
  • Legacy BI files (AdminBIDashboardManager.jsx, bi-dashboard-templates.js,
    chart components) were handled in a prior refactoring pass
