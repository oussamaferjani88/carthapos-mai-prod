────────────────────────────────────────────────────────────────────────────────────────
1.1 DASHBOARD
────────────────────────────────────────────────────────────────────────────────────────

CURRENT IMPLEMENTATION:
- Single React component (551 lines) with inline Card/Badge definitions
- Uses POSConfiguration for theming
- Mix of demo data (preview mode) and real DB queries (production mode)
- 4 KPI cards: totalSales, totalRevenue, productsCount, lowStockCount
- Bar chart showing monthly revenue (Recharts)
- Recent orders list (last 5 sales from DB)
- Auto-refreshes on 'sale-completed' custom event

CURRENT UI:
- 4 stat cards in a 2x2 grid at the top
- Bar chart below the cards
- Recent orders below the chart
- French labels hardcoded
- No gradients, no glass effects, no animations
- All data is either demo or generic (no today/this week filtering)

CURRENT WORKFLOW:
1. Page loads → useEffect → loadDashboardData()
2. Queries total sales count and total revenue (ALL TIME — not filtered by day)
3. Queries products count
4. Queries low stock count (stock <= 5)
5. Queries recent 5 orders
6. Renders everything statically

EXISTING BACKEND:
- Direct SQL queries via window.electronAPI.query()
- No dedicated dashboard IPC handlers
- All queries are hardcoded SQL strings in the frontend
- No caching, no websocket, no live updates

EXISTING DATABASE SUPPORT:
- Reads from: sales, products
- No today-specific filtering
- No shift data read
- No customer stats read

CURRENT STRENGTHS:
+ Works in both preview and production mode
+ Basic layout is clean
+ Auto-refreshes after new sale
+ Uses real DB queries (not just demo)

CURRENT WEAKNESSES:
- Data is ALL TIME instead of today/this week (useless for daily operations)
- Only 4 KPIs — no profit, no average ticket, no active shift info
- No time-based charts (hourly/daily/weekly)
- No low stock alerts, no top products
- Dashboard is static, no real-time feel
- No cash drawer status
- No quick actions (open cash register, new sale, etc.)
- Inline Card/Badge components duplicate shadcn/ui

MISSING FEATURES:
- Today's sales (filtered by current date)
- Active shift status
- Cash drawer status
- Best selling products
- Low stock alerts
- Average ticket
- Profit/expense tracking
- Real-time refresh (polling or SSE)

- Barcode search integration
- Table selection modal
- Customer assignment
- Discount handling (amount or percentage)

- Payment method popup
- Cart shows: item name, unit price, quantity controls, line total
- Footer area shows: subtotal, discount, tax, total, checkout button

CURRENT WORKFLOW:
1. Load products, tables, families from DB
2. Display product grid with category filtering
3. Cashier clicks product → adds to cart
4. Can select table (optional), customer (optional)
5. Can apply discount (amount or %)
6. Can hold order (park it for later)
7. Checkout → payment method selection → confirmPayment()

EXISTING BACKEND:

- Reads from: products, categories, restaurant_tables, product_families
- Writes to: sales, sale_items, restaurant_tables (status update)

+ Discount handling (amount and percentage)

- No receipt printing on payment (no thermal printer integration in flow)
- No refund/void/return functionality
- No quick quantity buttons (1, 2, 3, 5, 10)
- Product cards lack: stock status, availability indicator
- No favorites/recent products section
- No product modifiers in the sales flow (modifiers exist in MenuManagement but aren't used here)
- No kitchen notes / special instructions per item
- No order notes
- Payment popup is basic — no cash denomination calculation
- No receipt preview before payment
- Product search is basic text search (no barcode scanner focus)
- No split payment
- No quick cash amounts (5€, 10€, 20€ buttons)
- Keyboard shortcuts are limited

MISSING FEATURES:

- Quick quantity buttons
