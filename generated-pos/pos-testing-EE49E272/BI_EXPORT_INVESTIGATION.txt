1.2 Where the execution stops

  The SQL runs successfully but returns zero rows because no code
  writes to cash_drawer_events during normal shift operations.

1.3 Root cause

  DUAL ROOT CAUSE:

  ROOT CAUSE A — Wrong table for the expected data:

    The user's "opened and closed the cash register" operations
    are SHIFT operations. They write to the `shifts` table via
    `caisse:open-shift` and `caisse:close-shift` handlers
    (ipc-cash-register-handlers.cjs:22,44).

    The BI export reads from `cash_drawer_events` table, which is
    designed for physical cash DRAWER events (drawer open/close/count),
    not shift events.

    The `shifts.csv` dataset correctly shows all shift data (confirmed
    by the user). The cash_drawer_events table is a DIFFERENT concept.

  ROOT CAUSE B — Missing user_name in INSERT (minor, only affects
  physical drawer opens):

    The only handler that writes to cash_drawer_events table is
    `hardware:openCashDrawer` (ipc-hardware-handlers.cjs:278-292).
    Its INSERT (line 284) is:

      INSERT INTO cash_drawer_events
        (user_id, action, amount_expected, amount_actual, notes)
      VALUES (?, 'open', NULL, NULL, ?)

    The `user_name` column is NOT NULL (per schema at
    ElectronDatabaseManager.cjs:837) but is OMITTED from the INSERT.

    In SQLite, omitting a NOT NULL column from INSERT is equivalent
    to inserting NULL, which violates the NOT NULL constraint.
    The INSERT silently fails (caught at line 290, returns
    {success: false}).

    EVEN IF this bug were fixed, the user's shift operations would
    still not populate this table.

1.4 Evidence

  • ipc-cash-register-handlers.cjs:22-41  — caisse:open-shift → writes to `shifts`
  • ipc-cash-register-handlers.cjs:44-82  — caisse:close-shift → writes to `shifts`
  • ipc-hardware-handlers.cjs:278-292     — hardware:openCashDrawer → writes to `cash_drawer_events`
  • ElectronDatabaseManager.cjs:833-848   — cash_drawer_events table schema (user_name NOT NULL)
  • ElectronAuthManager.cjs:670-697       — logCashDrawerEvent() → writes to cash_drawer_events (9 cols)
    (but this method is only called from log-cash-drawer-event IPC, which the UI NEVER calls)
