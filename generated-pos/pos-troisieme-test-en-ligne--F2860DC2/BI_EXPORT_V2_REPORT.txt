3. DATASET REGISTRY DOCUMENTATION
================================================================================

  BiDatasetRegistry.cjs is the SINGLE SOURCE OF TRUTH for all datasets.

  Each registry entry declares:
  ┌──────────────────┬──────────────────────────────────────────────────────┐
  │ Field            │ Description                                          │
  ├──────────────────┼──────────────────────────────────────────────────────┤
  │ key              │ CSV filename (without .csv)                          │
  │ sql              │ Complete SQL query for data extraction               │
  │ module           │ Module dependency (null = always included)           │
  │ businessTypes    │ Array of business types, or 'all'                   │
  │ category         │ 'fact' or 'dimension'                                │
  │ description      │ Human-readable description                          │
  │ required         │ Whether this dataset must always be present          │
  │ mapper           │ Name of mapper function in BiDataMapper              │
  └──────────────────┴──────────────────────────────────────────────────────┘

  Resolution algorithm:
    1. Core datasets (sales, sale_items, products, customers, inventory,
       categories, product_families) are ALWAYS included.
    2. Non-core datasets are included if:
       a. businessTypes === 'all' OR businessType is in the array
       b. Module dependency is null OR module is in enabledModules

  To add a new dataset in the future:
    1. Add schema to BiSchemaContract.cjs SCHEMAS object
    2. Add mapper to BiDataMapper.cjs + MAPPER_DISPATCH
    3. Add registry entry to BiDatasetRegistry.cjs DATASETS Map
    Done. No handler changes needed.

================================================================================

  User clicks "Export BI"
         |
  BiExportModal opens
         |
  User clicks "Generer l'export"
         |
  ipcRenderer.invoke('bi:export')
         |
  IPCBiExportHandler.runExport(options)
         |
    [1] Load app-config.json
    [2] Resolve businessType + enabledModules
    [3] BiDatasetRegistry.resolveExportDatasets()
    [4] Batch 1 (parallel): sales, products, customers
    [5] Batch 2 (parallel): categories, product_families
    [6] Remaining datasets (sequential, may depend on above)
    [7] BiValidator.validateAll()
    [8] Generate CSVs (schema-driven column order)
    [9] Build metadata v2
    [10] Create ZIP
    [11] Return result with validation report
