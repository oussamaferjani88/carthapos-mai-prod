conservées à l'identique ; seule l'UI/UX est restructurée.

4. FONCTIONNALITÉS PRÉSERVÉES (aucun changement d'API ni de logique métier)
--------------------------------------------------------------------------------
  - Chargement GET /bi-requests/:id + bouton Actualiser + polling 6 s sur
    PROCESSING_ETL / DATA_REVIEW / GENERATING_DASHBOARD.
  - Vérifier le paiement   PATCH /bi-requests/:id/payment { paymentMethod }
  - Demander des infos     PATCH /bi-requests/:id/request-info { adminNotes }
  - Approuver              PATCH /bi-requests/:id/approve { adminNotes }
  - Rejeter                PATCH /bi-requests/:id/reject { adminNotes }
  - Notes admin            PATCH /bi-requests/:id/status { adminNotes }
  - Assistant ETL complet (wizard) : pages Step2Validation..Step7LoadConfirm
    inchangées, toujours encapsulées par EtlStepsWorkflow.
  - Préparer le dashboard  POST /bi/dashboards/generate-from-upload { uploadId }
  - Aperçu dashboard       embed GET /bi/dashboards/:id/embed (iframe)
  - Provisionner           lien /bi-dashboard/:id/assign (AdminDashboardAssign)
  - Publier                POST /bi/dashboards/:id/publish
  - Télécharger ZIP        GET /api/bi-uploads/:id/download
  - Journal / validation / résumé entrepôt (GET /bi-uploads/:id/logs,
    /validation-report, /summary) dans les zones repliables.
  - Historique (event history) conservé en chronologie.
  - Conditionnel ETL : isEtlProcessing masque Sidebar + cartes Info/Source/
    Dashboard/Historique et met le stepper sur l'étape 3 pendant le traitement.

5. CHANGEMENTS UI/UX
--------------------------------------------------------------------------------
  - En-tête « SaaS » avec badge de statut coloré + menu « Actions » unifié
    (remplace la carte « Actions » séparée).
  - Espace principal unique piloté par le statut (l'utilisateur ne voit que les
    actions pertinentes à l'état courant), au lieu d'une pile de cartes figées.
  - Stepper 7 étapes redessiné avec pastilles + connexions + bannière
    terminale / erreur.
  - Sidebar sticky compacte : Résumé / Paiement / Demande client / Notes admin.
  - Uploads en lignes compactes avec sections repliables (Journaux ETL,
    Rapport de validation, Résumé entrepôt).
  - Aperçu du dashboard repliable directement dans la carte.
  - États terminaux (COMPLETED / REJECTED / CANCELLED) rendus proprement avec
    badge d'erreur sur le stepper en cas d'échec.

6. COMPORTEMENT PAR ÉTAT
--------------------------------------------------------------------------------
  PENDING_REVIEW      : workspace review (paiement si manquant + CTA approuver +
                        demander infos + rejeter) ; sidebar + grille complète ;
                        stepper étape 1 active.
  APPROVED            : assistant ETL (wizard) ; isEtlProcessing vrai ->
                        grille + sidebar masquées, stepper étape 3 active.
  PROCESSING_ETL      : panneau de progression ETL (phases) ; stepper étape 3 ;
                        grille masquée ; polling.
  DATA_REVIEW         : panneau succès + tuiles stats + « Préparer le
                        dashboard » ; grille visible ; polling.
  GENERATING_DASHBOARD: spinner génération ; grille visible ; polling.
  READY_FOR_REVIEW    : aperçu + provisionner + publier.
  PUBLISHED           : panneau « publié » + carte dashboard avec badges.
  COMPLETED           : panneau terminal succès (remboursement si licence nulle).
  REJECTED            : panneau terminal erreur + bannière d'erreur
                        (stylée) + stepper erreur.
  CANCELLED           : panneau terminal (annulé).
