           Unique constraint: @@unique([exportId, saleId]) for idempotent ETL.

  Column          Prisma Type    SQL Type         Optional  Description

  id              String         TEXT              No        PK, auto-generated CUID
  tenantId        String         TEXT              No        Client tenant identifier
  exportId        String         TEXT              No        Source export/batch ID

10. ETL DATA FLOW SUMMARY
════════════════════════════════════════════

  POS System (Electron)
    │
    │ CSV Export: sales.csv, products.csv, inventory.csv,
    │             appointments.csv, kitchen_orders.csv, suppliers.csv
    ▼
  ZIP Upload → bi_uploads (status: UPLOADED)
    │
    ▼
  ETL Pipeline
    │
    ├── Step 1-3: Extract ZIP, validate metadata & schema
    │
    ├── Step 4: Load DIMENSIONS (upsert)
    │   ├── dim_time       ← upsert by date
    │   ├── dim_clients    ← upsert by tenantId
    │   ├── dim_products   ← upsert by composite key tenantId+productId
    │   └── dim_suppliers  ← upsert by composite key tenantId+supplierId
    │
    ├── Step 5: Load FACTS (upsert)
    │   ├── fact_sales           ← upsert by @@unique([exportId, saleId])
    │   ├── fact_inventory       ← upsert by @@unique([exportId, rowIndex])
    │   ├── fact_appointments    ← upsert by @@unique([exportId, rowIndex])
    │   └── fact_kitchen_orders  ← upsert by @@unique([exportId, rowIndex])
    │
    └── Step 6: Mark upload COMPLETED

11. KEY DESIGN NOTES
════════════════════════════════════════════

  • Multi-tenancy: All warehouse tables use tenantId + exportId
    for full isolation between clients

  • Idempotent ETL: All dimensions use upsert; all facts use
    upsert with @@unique constraints → safe to re-run

  • Conformed dimension: dim_time shared across all 4 fact
    tables, enabling cross-fact time-based analysis

  • dim_suppliers: Standalone dimension (no FK relations in
    Prisma), queried directly by warehouse service

  • Metabase compatibility: Warehouse queries are designed for
    direct consumption by Metabase dashboards

  • Business types: Different fact tables apply to different
    sectors — fact_sales and fact_inventory are universal,
    fact_appointments for salon/pharmacy, fact_kitchen_orders
    for restaurant/cafe
