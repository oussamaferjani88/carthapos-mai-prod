4. JWT FLOW
================================================================================
  Client:
    apiLogin/apiRegister -> backend returns { token, user, client }.
    saveAuthSession stores token in authToken.
    biFetch and axios attach:  Authorization: Bearer <token>.
  Backend:
    optionalAuth (middleware/auth.js verifyToken) populates req.user
    { id, username, email, role } on all BI routes.
    resolveClientId(req) (utils/identity.js) order:
      JWT req.user -> X-User-Id header -> userId body/query.
    Finds Client by userId and returns client.id; if no Client row exists,
    falls back to the raw user id, so a request is never attributed to
    another client.
  Scoping: bi-requests list, bi-dashboards list/detail, bi-notifications,
  bi-assignments all derive the tenant from resolveClientId. A forged
  clientId in query/body cannot widen the scope.
