FIGURE 2: fig:auth-sequence
-----------------------------------------------------------
Type: UML Sequence Diagram
Filename: figures/ch6-auth-sequence.png
Caption: Sequence of authentication and route authorization

Description:
Draw a UML sequence diagram showing the full auth flow: login + subsequent request.

LIFELINES:
  User -> Login Endpoint -> Password Validation -> JWT Generation ->
  HttpOnly Cookie -> Response

  Then for subsequent requests:
  Browser -> Middleware -> Token Verification -> Permission Check -> Controller

SEQUENCE - LOGIN:
  1. User sends POST /api/auth/login with username + password
  2. Login endpoint queries User by username
  3. bcrypt.compare(password, user.password)
  4. If match: generate JWT with { userId, username, role }
  5. Set HttpOnly cookie with JWT token
  6. Return response: { user: { id, username, email, role }, permissions: [...] }

SEQUENCE - SUBSEQUENT REQUEST:
  7. Browser sends request with cookie header
  8. Auth middleware extracts JWT from cookie
  9. jwt.verify(token, JWT_SECRET)
  10. If SUPER_ADMIN role: bypass all permission checks
  11. If other role: query UserPermission table for user permissions
  12. Check if required permission key is in user permissions
  13. If authorized: pass to controller
  14. If unauthorized: return 403 Forbidden

Use two fragments: LOGIN flow and SUBSEQUENT REQUEST flow.
Show the cookie being set and sent back.

FIGURE 13: fig:dashboard-provisioning
-----------------------------------------------------------
Type: Flow Diagram
Filename: figures/ch6-dashboard-provisioning.png
Caption: BI dashboard provisioning workflow

Description:
Draw the Metabase dashboard provisioning flow.

STEP 1: Template Selection
  - Select business-type template (BiDashboardTemplate)
  - Template has metabaseDashboardId, KPIs, dimensions, facts

STEP 2: Collection Creation
  - Create per-client Metabase collection
  - Name: "{clientName} Dashboards"

STEP 3: Dashboard Deep-Copy
  - Call Metabase API: POST /api/dashboard/:id/copy
  - is_deep_copy: true
  - Copies all cards, filters, layout

STEP 4: Tenant Filter Baking
  - For each card in the copied dashboard:
    - Find tenantFieldId for the tenantId column
    - Inject MBQL filter: ["=", [field tenantFieldId], tenantId]
    - For native SQL cards: inject WHERE "tenantId" = '<value>'

STEP 5: Collection Assignment
  - Move copied dashboard into client collection
  - Set permissions (client can view only)

STEP 6: Client Consumption
  - Client accesses dashboard via embedded/public link
  - tenantId filter ensures only client data visible

Show as a vertical flow with Metabase API calls as dashed arrows.
Highlight the tenant filter baking step.
