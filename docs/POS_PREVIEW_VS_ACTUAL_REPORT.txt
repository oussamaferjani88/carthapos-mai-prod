Objet     : Vérifier que l'aperçu "live" de la phase 3 (Personalisation) du
            customizer admin reflète fidèlement le POS Electron généré.

--------------------------------------------------------------------------------
1. VUE D'ENSEMBLE
--------------------------------------------------------------------------------
- Aperçu admin :  D:\Carthapos\admin\src\components\pos\preview\
  Pure vitrine React + Tailwind v4, données DÉMO statiques, aucun accès
  Electron/SQLite. But : montrer la structure finale (shell + pages).
- POS réel     :  D:\Carthapos\pos-template\
  Electron + React 18 + Vite + Tailwind, HashRouter, pages lazy, IPC SQLite
  en production / mode "preview" (mock) dans le navigateur.
- Le préfixe "POS" des modules admin correspond aux composants préfixés
  "POS" / pages du POS réel. C'est le miroir visuel.

6. SECTION E — DIFFÉRENCES NOTABLES & LIMITES
--------------------------------------------------------------------------------
1. 13 modules du POS réel n'ont pas de miroir dans l'aperçu admin
   (Barcode, QuickService, Takeaway, Loyalty, Kitchen, Appointments,
   Services, PaymentAdvanced, GiftCards, Prescription, Production,
   Suppliers, Hardware/Security/SystemDiagnostics).
2. 12 modules d'aperçu n'existent que côté admin (extensions prévues :
   MultiStore, Transferts, Variantes, Promotions, SplitPayments, TVA,
   Hors Ligne, Personnel, Balance, Séries & Lots, Réservations, Location).
3. 5 modules admin (Caisse, Calculator, Cart, QuickActions, Tools) ne sont
   PAS enregistrés dans le registre — ce sont des sous-composants de la
   page Ventes uniquement.
4. L'aperçu est 100 % statique/démo ; aucune donnée réelle, aucun
   IPC/SQLite, aucune authentification.
5. Le Drag & Drop et le switch Desktop/Tablette/Mobile ont été retirés
   de l'UI (souhait utilisateur) ; seul le bouton Actualiser flottant
   subsiste comme contrôle de prévisualisation.
6. L'ordre de navigation admin place "Marque" en premier, puis "Thème"
   (l'onglet par défaut du customizer est 'brand').
