1. OVERVIEW
   Removed all code related to the legacy React/Recharts custom dashboard
   generation system. The BI module now relies entirely on Metabase Community
   Edition for visualization. Dashboard generation is purely an association
   between a business type and a manually-created Metabase dashboard template.

2. DATABASE SCHEMA CHANGES (schema.prisma)
   Removed 3 fields from BiDashboard model:
   - dashboardType (String)
   - dashboardConfig (Json?)
   - generationSteps (Json?)
   BiDashboard now only stores: id, clientId, licenseId, uploadId,
   businessType, name, description, status, metabaseDashboardId, createdBy,
   assignedAt, createdAt, updatedAt.

3. FILES DELETED
   - backend/services/bi-dashboard-templates.js
       Legacy JavaScript dashboard template definitions (TEMPLATES object
       with section/type/chart config for restaurant, cafe, retail, pharmacy,
       salon). Replaced by BiDashboardTemplate database registry.
   - admin/src/components/charts/DashboardLineChart.jsx
       Recharts line chart component for legacy dashboard rendering.
   - admin/src/components/charts/DashboardBarChart.jsx
       Recharts bar chart component for legacy dashboard rendering.
   - admin/src/components/charts/DashboardPieChart.jsx
       Recharts pie chart component for legacy dashboard rendering.
   - admin/src/components/charts/DashboardAreaChart.jsx
       Recharts area chart component for legacy dashboard rendering.

     → No chart rendering, no warehouse data queries
     → Notifications sidebar preserved

   Admin Dashboard Viewer (AdminDashboardViewer.jsx)
     → Shows dashboard info + Metabase link
     → "Open in Metabase" button
     → No chart rendering

   Admin Dashboard Manager (AdminBIDashboardManager.jsx)
     → Lists dashboards with status, client, MB # badge
     → Create/link dashboards via template registry
     → Status workflow buttons
     → Template manager modal (register, activate, delete templates)

   Upload Portal (BiUploadPortal.jsx)
     → Upload ZIP, monitor ETL progress
     → Generate Dashboard button (synchronous, no progress modal)
     → Detail modal with linked request, job status, ETL logs

   Backend (bi-dashboards.js)
     → CRUD for BiDashboard records
     → generate-from-upload: looks up BiDashboardTemplate → creates association
     → metabase-link endpoint returns Metabase URL
     → Status transitions with validation
     → Notification generation on PUBLISH
     → NO /data endpoint, NO warehouse queries, NO chart config

   Metabase (External)
     → BI specialist manually creates dashboards
     → PostgreSQL warehouse connection (metabase_reader user)
     → Single source of truth for BI visualization
     → No programmatic dashboard creation (CE limitation)
