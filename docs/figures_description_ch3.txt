FIGURE 5: fig:usecase-client-generation
-----------------------------------------------------------
Type: Activity Diagram
Filename: figures/ch3-usecase-client-generation.png
Caption: Client-driven POS generation scenario.

Description:
Draw a detailed activity diagram for the client-driven POS generation flow.
Both the client and the administrator have direct access to the same POS
generator - the client can generate POS for his own business.

ACTORS:
  - Client (business owner - has direct access to the POS generator)
  - Administrator (operator - also has access to the same generator)

ACTIVITY FLOW:

  1. Client registers / Administrator creates Client account
  2. Administrator creates License (sector, type)
  3. Administrator configures LicenseModules and LicenseConfiguration
  4. Client receives license key
  5. Client opens POS Generator page (or Admin does from admin portal)
  6. Client selects business sector (restaurant, cafe, retail, bakery, pharmacy, beauty/salon)
  7. System loads default modules for the sector
  8. Client reviews and adjusts module selection
  9. Client configures theme (colors, logo)
  10. Client clicks Generate
  11. Backend executes 8-stage pipeline: license validation, directory init, template copy, module filter, dependency install, theme customization, file patching, build
  12. System exposes generated application for download
  13. Client downloads installer (.exe)

Use swim lanes: Client lane, Admin lane, System lane.
Mark decision points (e.g., License valid? yes/no).
