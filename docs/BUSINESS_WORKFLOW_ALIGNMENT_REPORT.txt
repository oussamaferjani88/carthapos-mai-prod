================================================================================
5. Is BiAnalysisRequest Still Useful?
================================================================================

ANSWER: NO, for new records. YES, for historical data.

Rationale:
- Currently auto-created by etl-pipeline.js Step 5e after every ETL run
- The bi-dashboards.js route REQUIRES a completed BiAnalysisRequest before creating
  a dashboard (line 72-80: "Dashboard creation requires a completed BI analysis")
- In the target workflow, dashboards are auto-generated from templates after ETL
  without requiring an analysis step
- The model adds unnecessary complexity: create analysis -> complete it -> create dashboard

Recommendation:
- Keep the table for historical data (existing records)
- REMOVE Step 5e from etl-pipeline.js
- REMOVE the analysis requirement from bi-dashboards.js (line 72-80)
- Stop creating new BiAnalysisRequest records
- The bi-analysis.js route can remain for viewing historical data

================================================================================
6. When Should Dashboard Generation Happen?
================================================================================

ANSWER: AFTER ETL COMPLETES AUTOMATICALLY.

Workflow:
1. ETL completes successfully (status=COMPLETED)
2. System reads business_type from the upload
3. System looks up matching template in bi_dashboard_templates
4. System creates BiDashboard with status=GENERATED
5. Admin receives notification: "New dashboard ready for customization"
6. Admin opens Dashboard Manager, sees GENERATED dashboard
7. Admin customizes (add/remove widgets, modify KPIs, change layout)
8. Admin submits for review (status=READY_FOR_REVIEW)
9. Admin reviews and publishes (status=PUBLISHED)
10. Client receives notification

This is 80/20 hybrid: template provides base, admin tailors.
