[8] ROOT CAUSE #2: POSPreviewPage.tsx + Route MISSING
═══════════════════════════════════════════════════════════════════════════════════

  • POSPreviewPage.tsx does not exist in frontend/src/pages/pos/
  • Route /pos-preview does not exist in frontend/src/App.tsx
  → Navigating directly to /pos-preview = "Page Not Found"

  The standalone preview page is used by Admin as both a standalone route
  AND wrapped inside POSRealtimePreview. In Frontend, POSRealtimePreview
  imports POSPreview directly instead of POSPreviewPage, skipping the
  POSWithAuth wrapper — this is actually acceptable.

[9] ROOT CAUSE #3: Missing DragDropProvider + DndProvider Wrappers
═══════════════════════════════════════════════════════════════════════════════════

  Admin POSRealtimePreview.jsx wraps content:
    <DragDropProvider>
      <DndProvider backend={HTML5Backend}>
        <ErrorBoundary>
          {viewMode === 'pos'
            ? <POSPreviewPage ... />
            : <ReceiptDesignerPreview ... />
          }
        </ErrorBoundary>
      </DndProvider>
    </DragDropProvider>

  Frontend POSRealtimePreview.tsx:
    {viewMode === 'pos'
      ? <POSPreview ... />
      : <ReceiptDesignerPreview ... />
    }
    → NO DragDropProvider
    → NO DndProvider
    → NO ErrorBoundary

  Without DragDropProvider, any component calling useDragDrop() will throw:
    "useDragDrop must be used within a DragDropProvider"

  Currently POSPreview.tsx does NOT call useDragDrop() directly, but it passes
  isVisible as a no-op function. If drag mode is enabled, components will break.
