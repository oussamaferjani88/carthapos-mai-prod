================================================================================
0. EXECUTIVE SUMMARY
================================================================================

- The warehouse follows a simple star schema (fact tables + dim_time / dim_clients /
  dim_products) but is ONLY PARTIALLY wired: fact_sales carries a working date key
  (dimTimeId 2500/2500, 0 orphans) but has NO product key and NO client key
  (dimProductId and dimClientId are NULL on 100% of rows).
- There are NO database-level foreign-key constraints on any BI table; joins are
  by convention only and must be declared manually in Metabase.
- Data is clean (0 negatives, 0 NULLs on core sales columns, no duplicate sale IDs),
  but it is DEMO-scale and single-tenant in the warehouse:
    fact_sales 2 500 rows, fact_inventory 19 rows, fact_kitchen_orders 402 rows,
    fact_appointments 0 rows, dim_suppliers 0 rows.
- Inventory is unusable for stock/value/low-stock KPIs: stock = 0 on all 19 rows.
- Product-level and customer-level sales ARE present in the POS export itself
  (saleItems 7 358 lines, 100% with productId ; customers 14 ; customerId set on
  2 172/2 500 sales = 87%) but the ETL warehouse load DROPS those datasets:
  fact_sales has NO dimProductId and NO dimClientId. So those KPIs are "available
  at source, not materialized in the warehouse".
- Hour-of-day KPIs (peak hours, hourly sales) are NOT possible from the warehouse:
  dim_time stores date only (YYYYMMDD), no hour. Hour granularity exists only in
  the analytics cache (sale/hour fields parsed from POS timestamps), not in any
  SQL view.
- Metabase is installed and connected; 10 BI SQL views already exist.

VERDICT (short):
  Restaurant dashboard  : START (revenue-centric), with documented gaps. Customer
                          and true product-per-sale KPIs can be added ONCE the
                          ETL materializes the saleItems/customers datasets that
                          already exist in every POS export (see §1 upstream).
  Coffee shop dashboard : START with limitations (no hourly SQL, no customer in
                          warehouse; both available at export level only).
  Retail dashboard      : DO NOT START yet — inventory stock, suppliers missing
                          (also absent from the POS exports: stockMovements=0).
