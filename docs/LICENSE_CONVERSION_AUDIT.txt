================================================================================
1. SUMMARY OF WHAT WAS DONE
================================================================================

The license system was rebuilt from a broken, mock-based, symmetric-crypto
design (score 15/100) into an asymmetric, Ed25519-signed, backend-owned,
machine/USB-bound license system that the Electron POS actually verifies.

Headline results:
  - Signing: symmetric HMAC/AES with hardcoded secrets -> Ed25519 with a
    backend-only private key and a per-build embedded public key.
  - Binding: unbound "machineId" free text -> real machine fingerprint +
    real USB device identity, enforced at runtime in Electron.
  - Lifecycle: no lifecycle at all -> CREATED/ISSUED/ACTIVATED/ACTIVE/
    SUSPENDED/REVOKED/REPLACED/EXPIRED with full audit history.
  - Enforcement: gate force-disabled + stub validator -> local Ed25519 verify +
    status gate + expiry + binding + offline grace + clock-rollback detection.
  - Admin: read-only list -> full management UI (lifecycle actions, history,
    real signed license file download).
  - Mocks removed: SIG=BYPASSED-FOR-WEB-DEPLOYMENT in admin/frontend generators,
    DEV-LICENSE/VALID-LICENSE fallbacks in the POS, dead ElectronLicenseManager,
    duplicate legacy stacks.

3. NEW ARCHITECTURE (END TO END)
================================================================================

  Admin creates license (wizard / Licenses page)
    -> POST /api/licenses  {clientId, sector, licenseType, expirationDate,
                             bindingType: MACHINE|USB|HYBRID, moduleIds,
                             configuration}
    -> DB row: status ISSUED, issuedAt set, legacy=false, licenseVersion=1
    -> auto-issue: generateLicenseFile() signs payload with the Ed25519 private
       key (backend only) and stores signature + signedLicensePayload + pubkey
       fingerprint on the row.
  POS build
    -> ThemeCustomizer embeds security.licensePublicKey, security.licenseServerUrl
       (http://localhost:3001) and security.requireUSBLicense into app-config.json.
  Delivery
    -> Admin downloads the signed file (license-<KEY>.key) or writes it to USB
       (USBManager / USBManager.jsx).
  Activation (first run of the POS)
    -> Electron reads the signed file (USB for USB/HYBRID, userData copy for
       MACHINE), verifies the signature locally, detects binding unset
       (reason ACTIVATION_REQUIRED), calls POST /api/licenses/:id/activate with
       the computed machineFingerprint and/or usbDeviceId, then re-fetches the
       re-signed file via /generate-file and stores it locally (MACHINE).
  Runtime (every start)
    -> validate-license IPC -> LicenseVerifier.validateLocal(): local verify,
       no network required for a signed, un-expired, correctly-bound license.
  Online refresh (opportunistic)
    -> On offline-grace exhaustion or forced validation, POST
       /api/licenses/:id/validate with {machineFingerprint, usbDeviceId} to sync
       server-side REVOKED/SUSPENDED/EXPIRED state.

4. CRYPTOGRAPHIC LAYER (Ed25519)
================================================================================

  Key material:
    - Private key: only on the backend. Loaded from LICENSE_PRIVATE_KEY_FILE
      (config/license-private.pem, chmod 0600) or LICENSE_PRIVATE_KEY env.
      keys.js THROWS if neither is configured - no hardcoded fallback exists.
    - Public key: embedded in every generated POS via
      security.licensePublicKey (from LICENSE_PUBLIC_KEY env).
    - Fingerprint of the public key: 251736810bf16e58, stored on each license
      (publicKeyFingerprint) and in each license file for audit.

  Algorithm: Ed25519 (RFC 8032) via Node's built-in crypto (crypto.generateKeyPairSync
  'ed25519', crypto.sign/verify with null algorithm). Zero new dependencies.

  Deterministic signing:
    canonicalStringify() serializes the payload with sorted object keys at all
    depths, so signer (backend) and verifier (Electron) always hash identical
    bytes without JSON byte-equality. Signature is base64.

  Rules enforced:
    - Sign ONLY on the backend (private key never ships).
    - Verify ONLY locally in Electron (public key is safe to embed).
    - The POS never trusts client-supplied machineId/binding/expiration/status:
      all of those live in the SIGNED payload.
    - A file existing is NOT a valid license: presence + parse + signature +
      version + status + expiry + binding must all pass.

5. LICENSE FILE FORMAT
================================================================================

  JSON (pretty-printed), signed by the backend, verified in Electron:

    {
      "format": "carthapos-license",
      "version": 1,
      "publicKeyFingerprint": "251736810bf16e58",
      "payload": {
        "version": 1,
        "licenseId": "<cuid>",
        "licenseKey": "XXXX-XXXX-XXXX-XXXX",
        "clientId": "<cuid>",
        "clientName": "...",
        "sector": "...",
        "licenseType": "SUBSCRIPTION" | "LIFETIME",
        "bindingType": "MACHINE" | "USB" | "HYBRID",
        "machineFingerprint": "<sha256[0:32]> or null",
        "usbDeviceId": "<sha256[0:32]> or null",
        "modules": [ { id, name, displayName, category, isCore, isEnabled } ],
        "configuration": { businessName, logo, currency, language, timezone, taxRate },
        "issuedAt": "<ISO>",
        "expirationDate": "<ISO> or null",
        "status": "ISSUED" | "ACTIVATED" | "ACTIVE" | ...
      },
      "signature": "<base64 Ed25519>"
    }

  The file is a CARRIER: for MACHINE binding it is copied into the POS
  userData directory after activation; for USB/HYBRID it lives at
  <drive>/license.key and the drive must be present at runtime.

6. BACKEND: DATA MODEL + SERVICE + API SURFACE

  - status (LicenseStatus): CREATED, ISSUED, ACTIVATED, ACTIVE, SUSPENDED,
    REVOKED, REPLACED, EXPIRED, RESET.
  - isActive flag maintained alongside status (suspend/revoke/replace -> false).
  - machineFingerprint / usbDeviceId: real identity, written ONLY by the

  - activationCount, transferCount, maxTransfers (default 3).
  - signedLicensePayload, signature, publicKeyFingerprint, licenseVersion, legacy.
  - audit timestamps: issuedAt, activatedAt, suspendedAt, revokedAt,

  - LicenseActivationHistory (action, fromStatus, toStatus, performedBy, details).
  - LicenseValidationLog (isValid, reason, status, details) - one row per check.
  - LicenseTransferHistory (transferType, from/to machine + usb, authorizedBy).

6.3 REST surface (backend/src/routes/licenses.js, mounted at /api/licenses
    and /api/v1/licenses)
  GET  /                        list (client+modules+configuration included)
  GET  /active                  active list
  GET  /expiring                expiring-soon
  GET  /key/:licenseKey         by key
  GET  /client/:clientId        by client
  GET  /:id                     details
  GET  /:id/history             full audit history
  POST /                        create (createLimiter + Joi)
  POST /admin-create            admin create (same limits)
  PUT  /:id                     restricted update (rejects SECURITY_SENSITIVE_FIELDS)
  PUT  /:id/configuration       config update
  PATCH/:id/toggle              legacy toggle (isActive)
  DELETE /:id                   delete
  POST /:id/generate-file       sign/bind and return the license file
  POST /:id/regenerate          re-sign
  POST /:id/activate            bind machine/USB (validates identity requirements)
  POST /:id/deactivate          unbind -> ISSUED
  POST /:id/validate            server-side validation (writes ValidationLog)
  POST /:id/suspend | /resume | /revoke
  POST /:id/renew               set new expirationDate
  POST /:id/extend              add N days
  POST /:id/transfer            move binding to new machine/USB (transferCount++)
  POST /:id/reset-binding       clear binding -> ISSUED
  POST /:id/replace             new license + mark old REPLACED
  POST /:id/modules/:moduleId   attach | DELETE detach | PATCH toggle

  Rate limits: createLimiter on POST creates, licenseActionLimiter on
  generate-file/regenerate/activate/deactivate/suspend/resume/revoke/renew/
  extend/transfer/reset-binding/replace/module ops, licenseValidateLimiter on
  validate. Exported from src/middleware/rateLimiter.js.

  SECURITY_SENSITIVE_FIELDS (rejected by the generic PUT): machineId,
  machineFingerprint, activatedMachineId, usbSerialNumber, usbDeviceId,

  licenseVersion, lastValidationResult. The client can never self-edit binding,
  status, or signature through a generic update.

  ApiResponse contract is preserved: success/created -> {status, message, data};
  admin and frontend API wrappers unwrap {status:'success',data} -> data.

7. POS RUNTIME: VERIFICATION, BINDING, OFFLINE, ACTIVATION
================================================================================

7.1 validateLocal() - exact decision order (LicenseVerifier.cjs)
  1. Dev mode (CARTHAPOS_LICENSE_DEV_MODE=true): allow DEV-LICENSE (build-time
     escape hatch only).
  2. Find license source: USB/HYBRID -> USB carrier required; MACHINE -> local
     userData copy first, USB fallback.
  3. Parse file: format must be 'carthapos-license', payload + signature present
     -> else LICENSE_CORRUPTED.
  4. Public key must be embedded -> else INVALID_SIGNATURE.
  5. Ed25519 verify over canonical payload -> else INVALID_SIGNATURE.
  6. payload.version <= 1 -> else UNSUPPORTED_LICENSE_VERSION.
  7. Clock rollback: if now < persisted lastKnownGoodTime - 12h
     (CLOCK_ROLLBACK_TOLERANCE_MS) -> CLOCK_ROLLBACK.
  8. Status gate: REVOKED/REPLACED -> REVOKED; SUSPENDED -> SUSPENDED.
  9. Expiry: SUBSCRIPTION and now > expirationDate -> EXPIRED.
  10. Binding (_checkBinding):
        MACHINE: payload.machineFingerprint must equal the local fingerprint
                 (unset -> ACTIVATION_REQUIRED, mismatch -> MACHINE_MISMATCH).
        USB: carrier drive must be present (else USB_NOT_FOUND) and drive.deviceId
             must equal payload.usbDeviceId (else USB_MISMATCH); unbound carrier
             -> ACTIVATION_REQUIRED.
        HYBRID: USB check + MACHINE check.
  11. Offline grace (SUBSCRIPTION only): anchor = lastKnownGoodTime else issuedAt.
        If now - anchor > 30 days (DEFAULT_OFFLINE_GRACE_MS), try one online
        refresh (POST /validate, 8 s timeout); success -> valid, else
        OFFLINE_GRACE_EXPIRED.
  12. Persist lastKnownGoodTime = now; copy USB-read MACHINE license into userData.
  13. Valid -> { isValid:true, status:'ACTIVE', reason:null, license }.

  Note: a subscription that is refreshed online (or re-activated) inside the
  grace window keeps working offline; the grace clock starts at issue for fresh
  licenses.

7.2 activate()
  Finds + parses the signed carrier, requires licenseServerUrl, computes the
  local fingerprint (+ usbDeviceId from the carrier), POSTs
  /licenses/:id/activate {machineFingerprint, usbDeviceId}, then POSTs
  /licenses/:id/generate-file with the same identity to fetch the re-signed
  (bound) file. MACHINE: stores it in userData. Persists lastKnownGoodTime.
  Returns { isValid:true, status:'ACTIVATED', ... } or ACTIVATION_REQUIRED.

7.3 _apiUrl() is idempotent
  base 'http://localhost:3001' -> http://localhost:3001/api/...
  base 'http://localhost:3001/api' -> same. The /api prefix is never doubled.
  LICENSE_SERVER_URL must NOT include /api.

8. IPC CONTRACT (ELECTRON)
================================================================================

  Every license IPC method returns the canonical shape:

    { isValid: boolean, status: string|null, reason: string|null, license: Object|null }

  Channels (exposed by preload as window.electronAPI.*):
    validateLicense()  -> LicenseVerifier.validateLocal()
    activateLicense()  -> LicenseVerifier.activate()
    detectUSBDrives()  -> USBIdentityProvider.detectUSBDrives()

  Failure reasons (LicenseFailureReason enum in DB + local usage):
    NO_LICENSE, INVALID_SIGNATURE, EXPIRED, REVOKED, SUSPENDED,
    MACHINE_MISMATCH, USB_NOT_FOUND, USB_MISMATCH, HYBRID_BINDING_FAILED,
    CLOCK_ROLLBACK, OFFLINE_GRACE_EXPIRED, LICENSE_CORRUPTED,
    UNSUPPORTED_LICENSE_VERSION.
    Plus local-only ACTIVATION_REQUIRED (not present in the DB enum - see notes).

  useLicense.js flow:
    validateLicense() -> if isValid set license/isValid, else setError(reason).
    If reason === 'ACTIVATION_REQUIRED' -> attempt activateLicense().
    Web mode: reads window.__POS_CONFIG__.license if present; no synthetic
    DEV-LICENSE is granted.
  App.jsx gate: if (!isPreviewMode() && !licenseValid) render <LicenseCheck />.

12. SECURITY PROPERTIES AND THREAT MODEL (AFTER)
================================================================================

  Attack / concern                    Status after the conversion
  ----------------------------------  --------------------------------------------
  Forge a license                     Blocked: Ed25519; private key never ships.
                                      Public key only -> can't sign.
  Copy license file to another PC     Blocked for MACHINE/HYBRID (fingerprint
                                      bound + signed). USB binding ties the file
                                      to the drive deviceId (carrier copy alone
                                      fails USB_MISMATCH unless drive cloned).
  Modify license fields client-side   Blocked: everything lives in the signed
                                      payload; any edit breaks the signature.
  Tamper the signature/format         Blocked: INVALID_SIGNATURE / LICENSE_CORRUPTED.
  Edit status/expiry via admin PUT    Blocked: SECURITY_SENSITIVE_FIELDS rejected;
                                      only dedicated lifecycle endpoints change them.
  Expired license reuse               Blocked: signed expirationDate checked vs now.
  Revoked/suspended license           Blocked: status gate on payload + server-side
                                      validation refresh.
  Clock rollback to extend expiry     Mitigated: lastKnownGoodTime persisted; >12h
                                      rollback -> CLOCK_ROLLBACK.
  Long offline use                    Limited: 30-day offline grace anchored on
                                      last good validation / issue date.
  Patch Electron JS                   Out of scope (no code signing); mitigated by
                                      app.asar packaging. Documented limitation.
  Hardcoded secrets                   Removed: keys.js throws without env config.
  Unknown license version             Blocked: UNSUPPORTED_LICENSE_VERSION.

  Never-trusted-from-client fields: machineId, machineFingerprint, usbDeviceId,
  usbSerialNumber, isActive, expirationDate, status, lastValidatedAt - only the
  backend signs them; the POS only reports its locally computed identities.
