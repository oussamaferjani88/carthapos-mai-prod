4. LICENSE CREATION FLOW
═══════════════════════════════════════════════════════════════════

Route: POST /api/licenses (backend/routes/license.js, lines 413-569)

  Parameters:
    • clientId (or userId for portal mode)
    • sector
    • licenseType (SUBSCRIPTION | LIFETIME)
    • expirationDate (required for SUBSCRIPTION)
    • modules[] (array of module IDs)
    • configuration { businessName, colors, fonts, etc. }

  Flow:
    1. Resolve client (by clientId admin mode, or auto-create in portal mode)
    2. Generate unique license key
    3. Create License record
    4. Create LicenseModule records for each selected module
    5. Create LicenseConfiguration record with filtered config fields

  Validation (Joi schema in backend/src/validators/licenseValidator.js):
    • clientId required
    • sector must be one of: restaurant, cafe, boutique, pharmacy, bakery, grocery, other
    • licenseType must be SUBSCRIPTION or LIFETIME
    • expirationDate required for SUBSCRIPTION, forbidden for LIFETIME

6. POS BUILD/GENERATION PIPELINE
═══════════════════════════════════════════════════════════════════

Trigger: POST /api/pos/generate (backend/routes/pos.js, lines 19-211)

  Three build modes:
    • LOCAL_BUILD=true    → Full local Electron build (.exe)
    • FAST_GENERATION     → Source code only, no build
    • Default             → Source + GitHub Actions build

  Pipeline (backend/utils/generators/index.js, 10 steps):

    Step 1 — Validate License (line 32)
      File: backend/utils/config/license-validator.js
      Checks: required fields, key format, client name, active status
      Processes configuration defaults for missing fields

    Step 2 — Initialize Project (line 36-43)
      File: backend/utils/generators/ProjectBuilder.js
      Creates: {GENERATED_POS_PATH}/pos-{clientName}-{licenseKey}/
      Cleans existing project if present

    Step 3 — Copy Template (line 50-53)
      File: backend/utils/generators/AssetManager.js (line 37-58)
      Recursively copies pos-template/ to project directory
      Skips: node_modules, .git, dist

    Step 4 — Create Config Files (line 64-66)
      File: backend/utils/generators/AssetManager.js (line 286-401)
      • Creates resources/config.json with business metadata
      • Creates public/app-config.json with embedded license data
        (license key, enabled modules, theme, database config)
      • Generates SQLite database filename from business name
      • Sets requireUSBLicense flag (default true, anti-piracy)

    Step 5 — Preload Script (line 55-57)
      File: backend/utils/generators/AssetManager.js (line 175-255)
      Creates Electron preload.cjs with IPC bridge for:
      database ops, license validation, window control,
      file system, settings, notifications

    Step 6 — Filter Modules (line 69-99)
      File: backend/utils/generators/ModuleFilter.js
      • Removes page files for disabled modules
      • Comments out navbar items for disabled modules
      • Cleans up route imports for disabled modules

    Step 7 — Install Dependencies (line 101-123)
      File: backend/utils/generators/DependencyManager.js
      • Updates package.json with build scripts
      • Installs Tailwind CSS v4 dependencies
      • Copies node_modules via robocopy (Windows) or npm ci

    Step 8 — Theme Customization (line 126-146)
      File: backend/utils/generators/ThemeCustomizer.js
      • Writes CSS custom properties as :root variables
      • Updates Tailwind config with theme colors
      • Patches component styles (Header, Sidebar, Button)
      • Generates app-config.json with full theme

    Step 9 — File Patches (line 148-189)
      File: backend/utils/generators/FilePatcher.js
      • Removes unnecessary files (pnpm-lock, .env.example, etc.)
      • Fixes Electron entry point files
      • Creates PostCSS config with @tailwindcss/postcss v4
      • Generates ESM vite.config.js
      • Copies critical shadcn/ui components
      • Patches package.json: unique name, productName, appId,
        artifactName, NSIS shortcutName

    Step 10 — Build (line 191-209)
      File: backend/utils/generators/BuildSystemManager.js
      • Validates build environment
      • Runs: npx vite build --mode production
      • Runs: npx electron-builder --win --x64
      • Finds .exe in dist/, release/, out/
      • Cleans up build directories

7. BUILD STATUS LIFECYCLE
═══════════════════════════════════════════════════════════════════

  pending       → Default on license creation
  building      → GitHub Actions triggered or local build started
  source_ready  → Source generation complete (fast mode, no build)
  completed     → Build succeeded (local or GitHub)
  failed        → Build failed (detected via GitHub status or local error)
  cleaned       → Build artifacts manually cleaned up

  Status polling: GET /api/pos/build-status/:licenseId
    • Checks stored buildRunId
    • Queries GitHub Actions API
    • Updates DB status accordingly

8. LICENSE FILE ENCRYPTION & VALIDATION
═══════════════════════════════════════════════════════════════════

File: backend/utils/license.js

  createLicenseFile() (lines 75-133):
    • Builds licenseData: { licenseKey, clientId, clientName, sector,
      type, expiry, modules[], config }
    • Creates HMAC-SHA256 signature
    • Creates SHA-256 checksum
    • AES-encrypts full payload
    • Returns encrypted string

  validateLicenseFile() (lines 136-189):
    • Decrypts AES payload
    • Verifies checksum (anti-tamper)
    • Verifies HMAC signature (anti-forgery)
    • Checks expiration for SUBSCRIPTION type
    • Checks isActive flag
    • Returns { isValid, data, message }

  validateMachineBinding() (lines 192-208):
    • Compares stored machineId against current machine hash
    • Machine ID = SHA-256 of { platform, arch, hostname,
      cpuCount, totalMemory }

9. LICENSE VALIDATION IN GENERATED POS
═══════════════════════════════════════════════════════════════════

  useLicense() hook (pos-template/src/hooks/useLicense.js):
    • Checks for window.electronAPI (Electron context)
    • If Electron: calls validateLicense() IPC handler
    • If valid: stores license data
    • If browser/dev: uses fallback "DEV-LICENSE"

  LicenseCheck component (pos-template/src/components/LicenseCheck.jsx):
    • Shows when validation fails
    • Provides USB drive detection button
    • Retry and Quit buttons
    • Checks for USB license key via IPC

  App.jsx integration (pos-template/src/App.jsx):
    • useLicense() on mount
    • If invalid + production: render LicenseCheck
    • If first-time setup: render SetupWizard
    • Else: render POS interface

11. FULL LICENSE LIFECYCLE (END TO END)
═══════════════════════════════════════════════════════════════════

  ┌─────────────────────────────────────────────────────┐
  │  1. ADMIN creates client (if not existing)           │
  │     ↓                                                │
  │  2. ADMIN creates license:                           │
  │     • Selects client                                 │
  │     • Chooses sector                                 │
  │     • Picks license type (LIFETIME / SUBSCRIPTION)   │
  │     • Selects modules from grid                      │
  │     • Configures theme (colors, fonts, language)     │
  │     • System generates unique license key            │
  │     • Creates License + LicenseConfiguration +       │
  │       LicenseModule records in DB                    │
  │     ↓                                                │
  │  3. ADMIN triggers POS generation:                   │
  │     • POST /api/pos/generate                         │
  │     • 10-step pipeline runs (validate → build)       │
  │     • Status: pending → building → completed         │
  │     ↓                                                │
  │  4. CLIENT downloads installer:                      │
  │     • GET /api/pos/download                          │
  │     • Receives .exe (or GitHub artifact)             │
  │     ↓                                                │
  │  5. CLIENT runs POS:                                 │
  │     • Electron app launches                          │
  │     • useLicense() validates embedded license        │
  │     • If valid: SetupWizard → Login → POS            │
  │     • If invalid: LicenseCheck (USB key prompt)      │
  │     ↓                                                │
  │  6. CLIENT uses POS with selected modules only       │
  │     (disabled modules: pages removed, nav hidden)    │
  └─────────────────────────────────────────────────────┘
