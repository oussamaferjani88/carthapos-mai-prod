FILES MODIFIED
--------------
1. backend/services/bi-data-utils.js (NEW)
   - parseInteger: strict /^-?\d+$/, rejects 12.5, 1e3, 1,200, +12, 12., abc123
   - parseDate: strict ISO calendar-validated YYYY-MM-DD[ T]HH:MM[:SS], rejects 2026-02-30
   - parseNumber: strict /^-?\d+(\.\d+)?$/, rejects 1e3, 1,200.50, +12, .5, 12.
   - normalizeEnum(value, domain): trim + collapse whitespace + lowercase + alias map
   - normalizeCategorical: lowercase canonical form
   - formatNumber, toDate, isEmpty, normalizeText
   - ENUM_MAPS: payment_method, sale_status, kitchen_status, priority, appointment_status, table_status
   - Aliases: espèces/especes→cash, carte→card, check→cheque, canceled→cancelled, done→completed

2. backend/services/bi-schema-registry.js
   - Wired parseInteger, parseNumber, parseDate into validateCsvTypes
   - integer branch: uses parseInteger (was lenient regex)
   - real branch: uses parseNumber (was inline regex — now single source)
   - datetime branch: uses parseDate (was Date.parse with silent rollover)

3. backend/services/data-preparation-service.js (FULL REWRITE)
   - All parsing goes through bi-data-utils (single source of truth)
   - DATASET_RULES: per-dataset rules for integer/numeric/date/text/categorical/enums/optionalDefaults/unknownDefaults/businessKey/checks
   - prepare() returns {preparedDatasets, changes, statistics, profiles, status}
   - Statistics: totalRowsProcessed, automaticFixes, warnings, errors, duplicatesRemoved
   - Profiles per dataset: rowCount, validRows, invalidRows, duplicateRows, duplicateBusinessKeys, missingValues, nullCount, distinctCount, numericStats
   - runReconciliation(): per-sale subtotal+tax−discount==total, per-line line_total==qty×unit_price, global grain report (item_total+vat−discounts vs sales grain)
   - Categorical normalization: trim + collapse whitespace + lowercase canonical
   - Duplicate business-key detection and reporting
   - Orphan-row skip logic not here (in etl-pipeline)

4. backend/services/etl-pipeline.js (MAJOR REFACTOR)
   - Imports: bi-data-utils (parseInteger, parseNumber, parseDate), data-preparation-service (DATASET_RULES)
   - New helpers:
     * _typedRows(datasets) — normalizes {header,rows} → plain arrays
     * _rowsToDatasets(prepared, rawDatasets) — re-wraps with headers
     * _prepareDatasets(datasets) — routes through dataPreparationService.prepare()
     * _errorSkipMap(changes) — builds Set of rowIndexes per dataset with ERROR severity
     * _collectDateKeys(datasets) — union of all date values across all datasets
     * _columnType(datasetKey, column) — looks up integer/numeric/date/text
     * _typedCorrection(datasetKey, column, rawValue) — re-types a reviewer correction
     * _applyCleanedCorrections(datasets, previewJson, report, skipMap) — merges overlay + legacy MANUALLY_CORRECTED changes, re-types, re-validates, applies to cleanedDatasets rows
     * _replayOverlays(previewJson, report, skipMap) — replays dimension/fact-section overlays with typing
     * _buildWarehouse(datasets, metadata, uploadId, changes) — in-memory dim/fact builder mirroring DB loaders (same coercion, same orphan/error skipping)
   - run(): after _validateDatasets, calls _prepareDatasets(), passes preparedDatasets + errorSkip to _loadDimensions/_loadFacts
   - _loadDimensions: typed rows, skip ERROR rows, dimTime auto-seeded from ALL date columns (not just sales), overlay support
   - _loadFacts: typed rows, skip ERROR rows, orphan sale_items/kitchen_order_items with unknown product_id skipped + warned, overlay support, returns {recordsLoaded, skippedRows, orphanWarnings}
   - prepareWarehouse: uses _prepareDatasets + _buildWarehouse, returns profiles/skippedRows/orphanWarnings
   - loadIntoWarehouse (T10): re-types + re-validates all corrections via _applyCleanedCorrections, replays dim/fact overlays via _replayOverlays, returns report {skippedRows, orphanWarnings, appliedCorrections, unresolvedIssues}

5. backend/routes/bi-uploads.js
   - POST /:id/correct: persists overlays into preview.corrections[section][table][rowIndex] for ALL sections (cleaned, dimensions, facts)
   - POST /:id/prepare: persists profiles, skippedRows, orphanWarnings into preview file
   - POST /:id/confirm-load: response now includes full report (skippedRows, orphanWarnings, appliedCorrections, unresolvedIssues)

6. backend/services/bi-schema-registry.js (minor)
   - Added parseNumber import for real-branch consistency
