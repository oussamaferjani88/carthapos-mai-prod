================================================================================
  POS GENERATION & DATABASE LOCATION REPORT
  How the POS is created and where the database file ends up
================================================================================

1. HOW A POS INSTANCE IS GENERATED
====================================

   The POS is generated from a template (pos-template/) into generated-pos/:

   [Admin UI] -> POST /api/pos/generate { licenseId }
      -> backend/ uses generators/ (8-stage pipeline)
      -> copies pos-template/ to generated-pos/pos-{client}-{licenseKey}/
      -> applies theme, filters modules, patches files
      -> runs: npm run build:safe (Vite build)
      -> runs: npx electron-builder --win --x64
      -> produces: release/POS System-Setup-1.0.0.exe

   The NSIS installer (pos-template/package.json line 174-194):
     - perMachine: true  (installs to Program Files)
     - allowElevation: true (runs as admin during install)
     - oneClick: false (user sees install wizard)
     - include: nsis-installer.nsh (custom installer script)

   Key files:
     pos-template/package.json             - electron-builder config (lines 102-199)
     pos-template/nsis-installer.nsh       - custom NSIS installer logic
     backend/utils/generators/index.js     - generation orchestrator (8 steps)
     backend/utils/generators/AssetManager.js   - copies template files
     backend/utils/generators/BuildSystemManager.js  - runs Vite + electron-builder


2. WHERE THE DATABASE FILE ENDS UP
====================================

   The DB location is determined by ElectronDatabaseManager.getDataFolderPath()
   in src/electron/ElectronDatabaseManager.cjs (line 516).

   LOGIC (in order of priority):

   A. INSTALLATION DIRECTORY (PREFERRED)
      Path: {exe folder}\data\{name}.db

      Conditions: The folder {exe folder}\data\ must exist AND be writable.

      How it becomes writable:
        - The NSIS installer (nsis-installer.nsh, line 7) creates:
            $INSTDIR\data\
            $INSTDIR\data\backups\
            $INSTDIR\data\logs\
        - Then runs icacls to grant BUILTIN\Users full control (line 29):
            icacls.exe "$INSTDIR\data" /grant:r "BUILTIN\Users:(OI)(CI)F" /T
        - Since the installer runs as admin (perMachine: true + UAC elevation),
          icacls succeeds and standard users can read/write the data folder.

      If the folder exists and is writable -> DB is at {installDir}\data\{name}.db
      This is the correct/successful path.

   B. APPDATA FALLBACK (GRACEFUL DEGRADATION)
      Path: %APPDATA%\{appname}\data\{name}.db

      Conditions: The installation directory data folder does NOT exist,
      or exists but is NOT writable.

      This happens when:
        - Running the .exe directly (not installed, e.g. USB/portable)
        - The installer failed to create the data folder (permissions, antivirus)
        - The app was installed by a user without admin rights (unlikely)

      The app uses app.getPath('userData') which is guaranteed writable.
      No UAC prompt is shown — it just silently falls back.

   DEVELOPMENT MODE:
      Path: D:/Carthapos/pos-template/dev-data/{name}.db
      (when running via npm run electron-dev)


3. HOW TO ENSURE THE DB IS IN THE INSTALLATION FOLDER
=======================================================

   KEY INSIGHT: The installer does ALL the work. The app just checks if the
   folder exists and is writable. No runtime UAC is needed.

   To guarantee the DB ends up in the installation folder:

   STEP 1: The NSIS installer must run successfully.
           - User must accept the UAC prompt during installation
           - This is a ONE-TIME thing during install, not during app launch
           - The installer creates $INSTDIR\data\ and sets permissions

   STEP 2: The nsis-installer.nsh must be included in the build.
           Verify in pos-template/package.json:
             "nsis": {
               "include": "nsis-installer.nsh"   (line 194)
             }
           And the file exists at: pos-template/nsis-installer.nsh

   STEP 3: The app code must NOT try runtime elevation.
           In ElectronDatabaseManager.cjs, getDataFolderPath() (line 516):
             - Checks if {installDir}\data\ exists and is writable
             - If yes: uses it (no UAC, no PowerShell)
             - If no: falls back to AppData silently
           This is the CURRENT state after the latest fix.

   STEP 4: Build and install.
           - Generate: POST /api/pos/generate or via admin UI
           - Install: double-click the generated .exe, accept UAC,
                      choose install directory (default: Program Files)
           - Launch: the app finds {installDir}\data\, writes the DB there

   VERIFICATION:
     After installation, check:
       {installDir}\data\           <- should exist with your DB files
       {installDir}\data\{name}.db  <- the SQLite database


4. FALLBACK SCENARIO (DB in AppData instead of installation folder)
====================================================================

   If the DB ends up in AppData instead of installation folder, it means
   one of these is true:

   PROBLEM 1: The installer didn't create the data folder.
     - Check if {installDir}\data\ exists
     - If not: the NSIS include isn't working, or installer failed
     - Fix: verify nsis-installer.nsh is correct and package.json has "include"

   PROBLEM 2: The data folder exists but is not writable.
     - Check permissions on {installDir}\data\
     - Right-click -> Properties -> Security tab
     - "Users" should have Full Control
     - Fix: run: icacls "{installDir}\data" /grant "Users:(OI)(CI)F" /T

   PROBLEM 3: The app didn't use the installation folder detection.
     - Check the console/logs for "DATABASE LOCATION DETECTION"
     - If you see "Falling back to AppData", it means the folder was not writable
     - If you see "Data folder is WRITABLE", it's correctly in install dir


5. SUMMARY OF KEY FILES
========================

   pos-template/nsis-installer.nsh
     - Creates data folder during installation (runs as admin)
     - Grants BUILTIN\Users full control via icacls
     - No changes needed — this already works

   src/electron/ElectronDatabaseManager.cjs
     - getDataFolderPath() (line 516): detects & returns data folder path
     - attemptPermissionFix() (line 480): now a simple check, no UAC
     - getAppInstallationRoot() (line 460): gets {exe dir} via app.getPath('exe')
     - Both methods are simplified to not attempt any runtime elevation

   The golden rule:
     INSTALLER creates the folder + sets permissions
     APP only checks and uses the folder (no prompts)
     If folder doesn't exist or isn't writable -> fallback to AppData
